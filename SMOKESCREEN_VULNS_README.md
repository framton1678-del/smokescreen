# Smokescreen Security Vulnerabilities - POC Suite\n\n## Overview\n\nThis directory contains proof-of-concept exploits for **critical vulnerabilities** in Stripe's Smokescreen HTTP proxy.\n\n**Repository**: https://github.com/stripe/smokescreen  \n**Status**: Open source, actively used in production at Stripe and other companies  \n**Impact**: All vulnerabilities allow complete bypass of proxy security controls\n\n---\n\n## Vulnerabilities Summary\n\n| # | Vulnerability | Severity | Status | Bounty Likelihood |\n|---|---|---|---|---|\n| 1 | ACL Range Logic Bypass | 🔴 CRITICAL | #236 | ⭐⭐⭐⭐⭐ |\n| 2 | Global Allow List SSRF | 🔴 CRITICAL | #146 (3+ years old!) | ⭐⭐⭐⭐⭐ |\n| 3 | Certificate CN Auth Bypass | 🟡 HIGH | Design flaw | ⭐⭐⭐⭐ |\n\n---\n\n## POC1: ACL Range Logic Bypass (CRITICAL)\n\n**GitHub Issue**: [#236](https://github.com/stripe/smokescreen/issues/236)  \n**Severity**: 🔴 CRITICAL  \n**Impact**: Complete bypass of IP-based access controls\n\n### Root Cause\n\nThe `classifyAddr()` function in `pkg/smokescreen/smokescreen.go` (lines 316-319) checks `AllowRanges` **BEFORE** `DenyRanges`. When an IP matches both ranges, the allow takes precedence.\n\n### Vulnerable Code\n\n```go\nfunc classifyAddr(config *Config, addr *net.TCPAddr) ipType {\n    // ...\n    if addrIsInRuleRange(config.AllowRanges, addr) {\n        return ipAllowUserConfigured    // ← Returns immediately\n    } else if addrIsInRuleRange(config.DenyRanges, addr) {\n        return ipDenyUserConfigured     // ← Never reached if in allow-range\n    }\n    // ...\n}\n```\n\n### Exploitation\n\n```bash\n# Vulnerable configuration\nsmokescreen --deny-range 1.0.0.0/8 --allow-range 1.1.0.0/16\n\n# Attack: Connect to 1.1.1.1 (exists in both ranges)\n# Expected: DENIED (deny-range should have priority)\n# Actual: ALLOWED (allow-range is checked first)\n```\n\n### Running POC1\n\n```bash\npython3 poc1_allow_deny_range_bypass.py localhost 4750 client.pem client-key.pem\n```\n\n### Impact\n\n- Bypass IP-based ACLs\n- Access restricted internal services\n- Circumvent network security policies\n- SSRF to internal infrastructure\n\n### Fix\n\nCheck deny-ranges FIRST and give them priority:\n\n```go\nif addrIsInRuleRange(config.DenyRanges, addr) {\n    return ipDenyUserConfigured\n} else if addrIsInRuleRange(config.AllowRanges, addr) {\n    return ipAllowUserConfigured\n}\n```\n\n---\n\n## POC2: Global Allow List SSRF (CRITICAL)\n\n**GitHub Issue**: [#146](https://github.com/stripe/smokescreen/issues/146)  \n**Severity**: 🔴 CRITICAL  \n**Status**: **OPEN SINCE SEPTEMBER 2021** (3+ years!)  \n**Impact**: SSRF to internal services, cloud metadata endpoints\n\n### Root Cause\n\nThe ACL decision logic in `pkg/smokescreen/acl/v1/acl.go` (lines 170-184) validates **hostnames only**, not resolved IP addresses.\n\nWhen checking `global_allow_list`, the proxy matches against the hostname glob pattern but never validates that the resolved IP is not internal.\n\n### Attack Flow\n\n1. **Setup**: `global_allow_list` contains `\"api.internal.com\"`\n2. **Attacker Control**: Attacker controls DNS for `api.internal.com`\n3. **DNS Poison**: Attacker makes `api.internal.com` resolve to `169.254.169.254` (AWS metadata endpoint)\n4. **Client Request**: Victim sends `CONNECT api.internal.com:443`\n5. **ACL Check**: Proxy checks: Is hostname in allow-list? → YES → ALLOW\n6. **DNS Resolution**: Proxy resolves `api.internal.com` → `169.254.169.254`\n7. **Bypass**: Connection is allowed despite targeting internal IP (ACL already approved)\n\n### Vulnerable Code\n\n```go\n// pkg/smokescreen/acl/v1/acl.go:170-184\nfunc (acl *ACL) Decide(args DecideArgs) (Decision, error) {\n    // Checks hostname ONLY\n    for _, dg := range acl.GlobalAllowList {\n        if HostMatchesGlob(args.Host, dg) {  // ← args.Host is hostname string\n            return Allow  // ← Returns based on HOSTNAME\n        }\n    }\n}\n\n// IP validation happens LATER in pkg/smokescreen/smokescreen.go:1290-1313\n// But by then, ACL has already approved it!\n```\n\n### Running POC2\n\n```bash\npython3 poc2_global_allow_list_ssrf.py localhost 4750 client.pem client-key.pem\n```\n\n### Real-World Impact\n\n```\nAttacker's Infrastructure:\n  1. Registers attacker.com\n  2. Creates DNS: api.internal.com → attacker.com\n  3. Server at attacker.com:\n     - Returns 200 OK to CONNECT requests\n     - Tunnels traffic to 169.254.169.254:80 (AWS metadata)\n\nVictim's Smokescreen Config:\n  global_allow_list: [\"api.internal.com\"]\n\nAttack Execution:\n  1. Client sends: CONNECT api.internal.com:443\n  2. Smokescreen checks hostname → allowed → APPROVE\n  3. Smokescreen resolves → 169.254.169.254\n  4. Opens tunnel to 169.254.169.254\n  5. Attacker gains access to AWS metadata:\n     - IAM credentials\n     - RDS passwords\n     - S3 bucket names\n     - Internal service endpoints\n```\n\n### Impact\n\n- 🔴 **SSRF to internal services**\n- 🔴 **Access to cloud metadata** (AWS, GCP, Azure)\n- 🔴 **Credential theft** (IAM roles, API keys)\n- 🔴 **Internal network reconnaissance**\n- 🔴 **Full system compromise**\n\n### Fix\n\nResolve hostname to IP **BEFORE** ACL approval:\n\n```go\nfunc checkIfRequestShouldBeProxied(...) (*ACLDecision, ...) {\n    // Step 1: Resolve hostname to IP\n    resolvedAddr, err := resolveTCPAddr(config, \"tcp\", hostPort)\n    \n    // Step 2: Validate IP is not internal\n    if !isPublicIP(resolvedAddr.IP) {\n        decision.allow = false\n        decision.Reason = \"internal IP not allowed\"\n        return decision\n    }\n    \n    // Step 3: THEN check ACL (with resolved IP context)\n    decision = checkACLsForRequest(config, sctx, req, destination)\n    \n    return decision\n}\n```\n\n---\n\n## POC3: Certificate CN Authentication Bypass (HIGH)\n\n**Code**: [main.go:16-24](https://github.com/stripe/smokescreen/blob/master/main.go)  \n**Severity**: 🟡 HIGH  \n**Impact**: Service impersonation, role hijacking\n\n### Root Cause\n\nThe `defaultRoleFromRequest()` function directly uses the certificate's CommonName (CN) field as the service role **without any validation**.\n\n### Vulnerable Code\n\n```go\n// main.go:16-24\nfunc defaultRoleFromRequest(req *http.Request) (string, error) {\n    if len(req.TLS.PeerCertificates) == 0 {\n        return \"\", errors.New(\"no certificate\")\n    }\n    // VULNERABLE: Directly uses CN as role, no validation!\n    return req.TLS.PeerCertificates[0].Subject.CommonName, nil\n}\n```\n\n### Exploitation\n\n```bash\n# Attacker creates certificate with arbitrary CN\nopenssl req -x509 -newkey rsa:2048 -days 1 -nodes \\\n  -out admin.pem -keyout admin-key.pem \\\n  -subj \"/CN=admin\"  # ← CN is completely attacker-controlled\n\n# Attacker connects with this cert\n# Smokescreen extracts role=\"admin\" from CN\n# If admin has 'open' policy → full access!\n```\n\n### Attack Scenarios\n\n**Scenario 1: Impersonate Admin**\n- Attacker creates cert with `CN=admin`\n- Smokescreen trusts CN and treats request as admin\n- If admin role has 'open' policy → full access\n\n**Scenario 2: Bypass Default Rule**\n- Config: `default_rule: enforce` (deny by default)\n- Config: `global_allow_list: [\"*.example.com\"]`\n- Attacker spoofs `CN=internal-api`\n- ACL decision uses wrong role, bypasses controls\n\n**Scenario 3: AllowMissingRole Bypass**\n- Config: `allow_missing_role: true`\n- Config: `default_rule: open`\n- Attacker creates any certificate\n- Gets full access with fabricated role\n\n### Running POC3\n\n```bash\npython3 poc3_certificate_cn_auth_bypass.py localhost 4750\n```\n\n### Impact\n\n- Service impersonation\n- Role hijacking\n- Bypass of role-based ACLs\n- Defeat mTLS purpose\n\n### Fix\n\nValidate CN against allowed services:\n\n```go\nfunc defaultRoleFromRequest(req *http.Request) (string, error) {\n    if len(req.TLS.PeerCertificates) == 0 {\n        return \"\", errors.New(\"no certificate\")\n    }\n    \n    cn := req.TLS.PeerCertificates[0].Subject.CommonName\n    \n    // Validate CN is in allowed services\n    allowedServices := []string{\"webhook\", \"api\", \"worker\"}\n    for _, service := range allowedServices {\n        if cn == service {\n            return cn, nil\n        }\n    }\n    \n    // CN not recognized\n    return \"\", fmt.Errorf(\"unknown service: %s\", cn)\n}\n```\n\nOr use certificate fingerprints:\n\n```go\n// Use certificate SHA256 fingerprint for identity, not CN\nfingerprintToServiceMap := map[string]string{\n    \"abc123...\": \"webhook-service\",\n    \"def456...\": \"api-service\",\n}\n```\n\n---\n\n## Setup & Testing\n\n### Prerequisites\n\n```bash\n# Requires Python 3.6+\n# Uses only standard library (socket, ssl,
